# v1.13.0 → v1.14.0 升级报告（后端契约升级）

> 需求来源：`BACKEND_UPGRADE_REQUIREMENTS_2026-11-09.md`（B-01 ~ B-11）
> 一句话：**加能力、收错误码，不改任何既有字段名**。
> 迁移与回滚细节见 [MIGRATION_NOTES.md](./MIGRATION_NOTES.md)；HTTPS 见 [DEPLOY_HTTPS.md](./DEPLOY_HTTPS.md)。

---

## 1. 前端要不要改？分三档

| 前端现状 | 是否必须改 | 依据 |
|---|---|---|
| v1.5.x 及更早（只判 HTTP 状态，不校验业务 `code`） | **不改也能跑** | 审计确认 `VodSyncApi.deliver()` 只判 HTTP 状态与 JSON 非空；本次所有新增字段纯新增 |
| 已按 v1.13.0 契约消费（读 `pagecount` / `list` / `detail`） | **不改也能跑** | 字段名一个没动；`page_size` 缺省从 30 改 18，但客户端固定传 18，等价 |
| 想用标签精确检索 / 能力门控 / 可读错误文案 | 需要改（见第 2 节） | 新能力默认不启用 |

**结论**：服务端可以先上线，客户端择机跟进。只有「想用新能力」才需要改代码。

## 2. 客户端要做的四件事（按优先级）

### ① 读 `/healthz.capabilities` 做能力门控（最重要的 10 行代码）

```kotlin
// 连接测试 / 启动时调一次，缓存 5~10 分钟
val caps: Set<String> = api.healthz().capabilities ?: emptySet()

// 详情页点标签
if ("tag_search" in caps) api.search(tag = clickedTag, source = slug)
else                      api.search(wd  = clickedTag, source = slug)   // 退化，不报错
```

`capabilities` 是数组（也接受 `{name: bool}` 对象形态）。**不要用 version 比较** ——
版本号只增不减，但能力可能被灰度关掉。

可用能力：`tag_search` / `backfill_play_from` / `play_line_filter` / `error_codes` /
`token_scope` / `star_tags` / `related` / `paging_v2`。

### ② 错误文案改用服务端给的 `message`

以前失败响应只有 `detail`，很多路径是「200 + code:1」或「422 + detail 数组」，
客户端只能统一弹「网络错误」。现在：

```json
{ "code": 40301, "error": "insufficient_scope", "detail": "该接口需要 admin 权限的 Token（当前 Token 为只读）",
  "message": "同上", "required": "admin" }
```

建议：`message ?: detail ?: "网络错误"`；分类埋点用 `error`（稳定英文串）。
失败判定：`statusCode >= 400 || code != 0`。

> ⚠️ 成功码从 `1` 变成 `0`。**如果客户端有 `code == 1` 判成功的逻辑，必须改成 `code == 0`**。
> 服务端提供 `API_SUCCESS_CODE=1` 可临时退回（不用回退镜像），但建议一次改干净。

### ③ 标签胶囊改用 `?tag=`

```diff
- GET /api/v1/search?wd=悬疑&source=ffzy&page_size=18
+ GET /api/v1/search?tag=悬疑&source=ffzy&page_size=18
```

区别：`wd` 是「片名含悬疑」（会把「悬疑喜剧」搜进来、又把「片名不含但标签是悬疑」的漏掉）；
`tag` 是按分隔符切开后**整段相等**。响应结构与 `/videos` 完全一致，`total_approximate` 恒 `false`，
空结果 200。

### ④ 控制台写操作改用 admin Token（不急着做）

`POST /api/v1/auth/tokens`（`scope=admin`）签发一枚专供控制台；浏览用 `scope=read`。
服务端默认 `TOKEN_SCOPE_ENFORCE=false`（全放行），所以**现在发不发都不影响功能**。
等上面这步做完、观察两个版本周期后，运维才会打开强制校验。

## 3. 服务端改了什么（给前端核对字段用）

| 项 | 变化 | 兼容性 |
|---|---|---|
| `/healthz` | 新增 `capabilities[]`；DB 降级时自动收缩 | 纯新增 |
| 错误响应 | 非 2xx + `{code, error, detail, message, field?, required?}`；422 改 400 | `detail` 保留，老代码不炸 |
| 成功码 | `1` → `0`（`API_SUCCESS_CODE` 可回退） | **需确认客户端不判 `==1`** |
| `/search`、`/videos` | 新增 `?tag=` | 纯新增，不传则行为不变 |
| 列表项 | 新增 `remarks`（= `vod_remarks`）、`vod_area`、`vod_year` | 纯新增 |
| 详情项 | 新增 `play_lines`（= `vod_play_list`）、`tag`（= `vod_tag`） | 纯新增（同值别名） |
| 剧集 | 新增 `from` / `type` / `playable` | 纯新增 |
| 分页 | `total_approximate` **恒出现**；`page_size` 缺省 18 | 语义明确化 |
| Token | 新增 `GET\|POST /auth/tokens`、`DELETE /auth/tokens/{id}`，`read`/`admin` 两档 | 纯新增，默认不校验 |

**没变的**：`list`、`detail`、`pagecount`、`total`、`original_index` 的语义；
`/api/v1/{slug}`（MacCMS 兼容）仍返回 `code:1`；`playable` 缺失/null 仍按可播处理。

## 4. 上线顺序（服务端视角）

```
1. 升级镜像（自动建表，不改既有列）            ← 客户端零改动即可运行
2. 标签索引后台回填（启动自动，可断点续跑）      ← 期间不声明 tag_search
3. 索引就绪 → /healthz 自动声明 tag_search      ← 客户端下次探测即切精确检索
4. HTTPS 双栈并行（8181 保持不动）
5. 观察两个版本周期后再考虑 TOKEN_SCOPE_ENFORCE=true
```

## 5. 回滚开关一览（都不需要回退镜像）

| 想关掉 | 环境变量 | 影响 |
|---|---|---|
| 标签检索 | `CAPABILITIES_DISABLE=tag_search` | 客户端退回 `wd`，接口仍可调 |
| 标签检索（彻底） | `TAG_SEARCH_ENABLED=false` | 接口与索引一并停用 |
| 成功码退回 1 | `API_SUCCESS_CODE=1` | 恢复 v1.13 行为 |
| Token 权限校验 | `TOKEN_SCOPE_ENFORCE=false`（默认） | 所有 Token 等价 admin |
| 启动回填 | `TAG_INDEX_ON_STARTUP=false` | 只能手动/CLI 回填 |
