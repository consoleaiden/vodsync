## 3. 文档之间的关系

```
                    ┌─────────────────────────┐
                    │  API_SPEC_FOR_AI.md  ★  │  权威接口定义（字段/语义/骨架）
                    └───────────┬─────────────┘
                                │ 精简版
                    ┌───────────▼─────────────┐
                    │     CLIENT_API.md       │  人读速查
                    └─────────────────────────┘
                                │ 机器可读
                    ┌───────────▼─────────────┐
                    │      openapi.json       │  由代码生成，勿手改
                    └─────────────────────────┘

  REVIEW_2026-11-07.md ──（第 8 节 W1~W4 落地）──▶ UPGRADE_..._v1.10.x.md ──▶ 前端对接
  REVIEW_2026-11-03.md ──（三个 P0 修复）─────────▶ v1.6.0（见 README 变更记录）
```

- **接口细节只信 `API_SPEC_FOR_AI.md`**。`CLIENT_API.md` 是它的精简版，为控制篇幅会省略边界情况。
- **审查/复盘报告是当时的时间切片**，里面的"现状"描述可能已被后续版本修掉；判断当前行为请看 README 变更记录和代码。
- **升级报告是一次性交付物**，不需要随版本维护；新的升级另起一份 `UPGRADE_<日期>_<版本>.md`。

## 4. 维护约定

发布新版本时，按此清单同步（缺一项就会出现"文档说 A、代码是 B"）：

| 变更类型 | 必须更新 |
|---|---|
| 任何版本号变更 | `app/__init__.py` → 重新生成 `openapi.json` → 本文档第 2 节表格 |
| 新增/修改接口或字段 | `API_SPEC_FOR_AI.md` + `CLIENT_API.md` + `openapi.json` |
| 新增环境变量 | `.env.example` + `README.md`「配置项」段 + `API_SPEC_FOR_AI.md` 环境变量速查 |
| 有部署动作（迁移/重算/新依赖） | 新增 `UPGRADE_<日期>_<版本>.md` + README「变更记录」 |
| 文档新增/改名 | 本索引 + `README.md`「项目结构」的 `docs/` 树 |

**命名规则**

- 接口文档：固定名，不带版本号（`API_SPEC_FOR_AI.md` / `CLIENT_API.md`），版本在文件头声明
- 一次性文档：`<类型>_<日期>_<版本>.md`，日期为 ISO 格式（`2026-11-07`）；跨补丁版本用 `x`（`v1.10.x`）
- 历史快照类（审查/复盘）**不删不改**，只在文件头标注"已归档"与本索引里说明修复状态
